# ADR-026: governed local submitted-seed dispatch

Status: Accepted reversible local engineering default.
Date: 2026-09-19.

[ADR-025](025-governed-local-seed-admission.md) admits a target but grants no collection permission. The next dependency in [30](../30-CRAWL-RENDER-CONTRACT.md), [33](../33-EVENT-JOB-CONTRACT.md), [34](../34-SECURITY-TENANCY-DATA.md) and [35](../35-QUALITY-SELF-AUDIT-GATES.md) is a separately governed submitted-page fetch. This checkpoint implements only its isolated local dispatch boundary. It does not widen the robots bootstrap exception.

A dedicated `http_seed_fixture_v1` handler and installed deterministic Skill permit one `http.fetch_public@1.0.0` call. Derive the exact target, normalized URL, current robots source and successor frozen bundle from the accepted seed-admission chain, never caller-supplied URL/target/evidence. Pin immutable source/context identities. Require current known robots rules and permission for the exact path, retained verified scope/robots bytes, current source and child releases, membership, freshness, audit and deletion eligibility. Recheck after unlocked artifact reads and before container creation, execution and socket opening. An immutable prior admission receipt alone cannot prove the current target is eligible.

Unique child identity follows the actual submitted target/admission, so alternate idempotency keys cannot create duplicate collection authority. The first HTTP reservation atomically claims the queued/admitted target for that exact job attempt and transitions it to fetching, incrementing its attempt count once. Subsequent current gates permit only that immutable claim. Recovery cannot reset a consumed Skill call, steal another attempt's claim or turn an unknown termination into a free slot. Preserve permanent worst-case HTTP charges and independent terminal accounting from ADR-014/020/022. Failed or uncertain execution does not mark a page visited.

The dedicated trusted broker accepts a configured local fixture port and derives the allowed exact seed path from the validated descriptor. The worker runs with network disabled and receives no URL authority, database credentials or secrets. Only one fixed GET is available, bounded by 5MiB decoded response and 20s; no redirects, inner retries or worker-selected destination. Local reviewed fixture identity restrictions remain mandatory. Public traffic, customer URLs and website writes remain blocked.

Dispatch returns operational metadata and independent container/socket termination accounting. It does not accept Evidence, project a PageSnapshot, complete the fetch job or complete the crawl. Existing bootstrap acceptance/projection must reject this handler. A later acceptance checkpoint must retain a private response handoff during a fresh authorized invocation; a digest-only dispatch receipt cannot reconstruct discarded bytes or authorize replay of a spent call. This separation is a verification checkpoint, not a product-completion claim.
