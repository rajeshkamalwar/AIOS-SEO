# ADR-023: governed local HTTP evidence acceptance

Status: Accepted reversible local engineering default.
Date: 2026-09-18.

[ADR-022](022-governed-local-http-bootstrap.md) establishes physical execution, not Evidence. Connect the trusted local broker to a separately credentialed collection acceptor under [26](../26-TEMPORAL-EVIDENCE-CONTRACT.md), [29](../29-SENSOR-CONNECTOR-CONTRACT.md), [30](../30-CRAWL-RENDER-CONTRACT.md), [33](../33-EVENT-JOB-CONTRACT.md), [34](../34-SECURITY-TENANCY-DATA.md) and [35](../35-QUALITY-SELF-AUDIT-GATES.md).

The host broker privately copies the observed bounded body and allowlisted response metadata and records collection time. The worker receives only the existing bounded metadata protocol. Canonical receipt fields use the admitted logical fixture URL; the immutable local profile, loopback fixture port and container invocation remain bound in the operational context. This is synthetic fixture evidence, never proof of a public website response.

Extend the independent terminal transcript with a digest of canonical HTTP receipt fields before Evidence ID allocation, exact body hash/length and observed instant. Acceptance must match that stored transcript and invocation/attempt/descriptor/build context. The transcript also binds the producer's worker-conformance verdict. Accepted response evidence requires valid worker conformance; an independently observed null-body transport failure may retain only its fixed failure receipt. Protocol violations cannot be accepted. Caller-supplied worker metadata cannot substitute for the observed body or headers. A terminal witness still requires independently confirmed container and socket cleanup; uncertain termination cannot accept data. Settlement is accounting only and cannot waive current authority.

Only a separate aios_http_acceptor credential may invoke the narrow acceptance function. The scheduler, worker and runtime cannot use it directly. Preflight and final commit recheck the original live fetch lease, current release/source/audit/deletion state and exact scope. Uploads hold only the shared maintenance fence, never the work or tenant clock lock. The trusted acceptor service owns full current audit-graph, external deletion-ledger and reviewed-retention validation; SQL provides additional scoped fencing, not a substitute raw acceptance API. Existing reviewed-fixture retention gates reject unreviewed bodies or opaque metadata before upload. Fixed sanitized transport error classes may be explicitly added to the finite fixture vocabulary; arbitrary exception text is never retained. No generic customer-content redaction claim is introduced.

Atomically persist compatible Evidence/Observation/HTTP acceptance records, immutable invocation mapping and outbox at one knowledge sequence. Exact replay returns the same accepted identities with no duplicate event; changed input conflicts. No raw content enters events or the public operational receipt. Observation state distinguishes transport failure, partial capture and observed HTTP status; HTTP404 alone is not transport failure.

The acceptance result consists of durable IDs. It does not complete the fetch child, parse robots, advance frontier, publish understanding or grant website-write authority. Those remain dependency-ordered work. Production activation, public TLS/DNS/egress verification and customer privacy approval remain separately gated.
