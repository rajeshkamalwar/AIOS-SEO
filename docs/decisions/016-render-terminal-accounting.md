# ADR-016: independent offline-render accounting authority

Status: Accepted reversible local engineering default.
Date: 2026-09-18.

Canonical [30](../30-CRAWL-RENDER-CONTRACT.md) and [33](../33-EVENT-JOB-CONTRACT.md) require a separate render lane, durable budgets and independently proven termination. Generic job reservations alone do not enforce render concurrency and allow scheduler-supplied actual charges. Extend the [HTTP authority pattern](014-http-terminal-authority.md) to a distinct local render accounting protocol. This resolves an implementation contract, not render selection or customer authority.

Each new navigation reservation permanently charges one render page,100 attempted requests and10MiB. Bound the run to20 navigations,2000 attempts and200MiB, with at most one unsettled navigation per run and two globally. Enforce run and tenant page/request budgets atomically, including other generic reservations. Retries consume new charges. Settling never refunds the worst-case charges; unknown actual request/byte measurements remain null. No late cleanup or restart resets occupied capacity.

The reservation has an immutable invocation ID and exact tenant/site/run/job/attempt/token, PageSnapshot, frozen bundle, offline profile and prepared-input SHA-256. Current lease, membership, release, deletion, audit and persisted source eligibility must pass. The trusted adapter reuses full source/audit and external deletion checks; SQL independently enforces accounting, exact scope/source identity and live run/lease/release gates. A direct SQL accounting allocation cannot certify source eligibility or confer dispatch authority. The supplied input digest is a pinned assertion at this accounting boundary, not independent proof of prepared bytes. A future producer must recompute input using the trusted persisted-source preparation path, compare it and recheck current authority immediately before GO. No scheduler-supplied hash grants execution or result acceptance.

A separate NOLOGIN-by-default render-supervisor database role binds the invocation before execution. Binding includes a unique supervisor process-instance UUID, actual Docker full container ID, immutable image digest, source-context hash and measured start time. Do not substitute a Docker CLI PID or mutable image tag for container/image identity. Narrow commands and immutable rows prevent scheduler/browser-authored witnesses or direct counter/refund writes. Do not grant supervisor credentials or the Docker socket to the browser.

A matching immutable terminal witness records measured finish time, termination kind, result digest and actual attempted requests/decoded bytes when known. It releases concurrency once only after the trusted supervisor independently confirms the owned container stopped and its resources were removed. Docker CLI exit, successful signal delivery, worker JSON, lease expiry and cancellation are insufficient. Uncertain engine or host state retains the slot. Identical transcript replay returns the original receipt; altered context conflicts. Terminal accounting after cancellation or revocation cannot authorize output acceptance or another dispatch.

This checkpoint tests the protocol using explicitly independent supervisor fixtures. It installs no actual container producer, public resource access, new render handler or Evidence writer. Existing project leases may exercise accounting fixtures with explicit budgets; API render budgets remain zero. A later local dispatcher needs explicit governed `render.observe` permission and immutable snapshot-specific job input, then must create the fixed isolated container paused, bind and recheck before starting. Preserve the existing network-none, nonroot, no-mount and bounded sandbox settings. Automatic page-role/template selection is not invented by this protocol.
