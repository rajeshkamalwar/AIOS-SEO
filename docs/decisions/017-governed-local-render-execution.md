# ADR-017: governed local offline-render execution

Status: Accepted reversible local engineering default.
Date: 2026-09-18.

The source bridge and [accounting protocol](016-render-terminal-accounting.md) do not authorize rendering. Implement one fixed `offline_render_v1` prerequisite handler under [28](../28-SKILL-MANIFEST-SPEC.md), [30](../30-CRAWL-RENDER-CONTRACT.md) and [33](../33-EVENT-JOB-CONTRACT.md). This does not release the draft parity Skill, select representative page roles automatically or enable public resource access.

A live project preparation lease may enqueue a separately governed local render child for one explicitly selected persisted snapshot. Ordinary enqueue still rejects render. The immutable descriptor pins source snapshot/bundle/observations/artifacts, raw and prepared digests/lengths, decoder/transformation, policy/profile and source context. Its complete digest participates in job idempotency. Raw service-role job insertion cannot bypass the required descriptor; descriptor substitution is forbidden.

Only the installed deterministic procedure with exact `render.observe@1.0.0`, read-only authority and local/discovery policies is eligible. Its one allowed invocation is cumulative across job attempts: reserving on one attempt consumes it even if execution later becomes uncertain. A retry cannot reset permission. Eligibility and tool permission are rechecked at admission, claim and immediately before start. Explicit test reviewer identities authorize only the synthetic profile; no canonical SEO capability is promoted or independently released by this fixture.

The Skill exposes only the `render.observe` tool. Trusted tool internals perform bounded, scoped preparation reads; no generic `artifact.read_scoped` tool is exposed and no fictitious durable artifact-tool counter is claimed. Two preparation passes verify retained bytes. A final metadata-only gate rechecks lease, release, descriptor, current source/audit/deletion, Site metadata and robots age after Docker inspection and immediately before start.

Create the fixed container without starting it. Bind its actual full ID and immutable image digest to the independent supervisor before GO. Verify the pinned seccomp policy and exact nonroot, network-none, read-only, capability, namespace, memory/CPU/process and temporary-storage configuration. No host bind mounts, production credentials, DB credentials or Docker socket enter the browser. Image/build configuration is trusted host configuration, not job/model input. Browser output is bounded and remains untrusted.

The producer heartbeats while managing execution; an authority failure aborts it. A Docker client close, killed client or worker assertion is insufficient termination proof. Inspect the owned container, stop it if necessary, confirm it stopped, remove it and independently confirm absence before issuing a terminal witness. Cleanup uses immutable identity and an invocation nonce, never an arbitrary caller-selected container. Uncertain create/engine/cleanup state retains capacity and produces no fabricated terminal receipt. This is not a host-loss recovery implementation.

Return only the [local operational execution receipt](../../spec/offline-render-execution.schema.json): invocation/container/terminal IDs, stdout digest, conformance, worker-reported state and `evidenceAccepted:false`. Conformance is not factual truth. It is not canonical `render.observe` result acceptance, Skill assessment, Evidence or RenderSnapshot. Domain artifact acceptance and atomic job completion are later dependencies; generic completion cannot mark this render child complete. The producer is callable local implementation, not an installed unattended dispatcher or recovery loop. A caller must not treat successful physical execution as product completion.
